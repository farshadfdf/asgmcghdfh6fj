FAST BERRY — نسخهٔ اولیه حفظ‌شده + بک‌اند سفارش/رسید/پرداخت

ساختار ظاهری index.html و style.css نسخهٔ اولیه حفظ شده است. این بسته برای Cloudflare Workers با Static Assets آماده شده است.

قابلیت‌های اضافه‌شده در کد:
- ثبت سفارش از طریق API و تولید کد پیگیری
- ذخیرهٔ سفارش و وضعیت در Cloudflare D1
- ذخیرهٔ فایل رسید در Cloudflare R2 (حداکثر 5MB، JPG/PNG/WEBP/PDF)
- پیگیری سفارش با کد
- پنل مدیریت برای مشاهده سفارش‌ها، مشاهده رسید، تغییر وضعیت و تنظیم اطلاعات پرداخت

راه‌اندازی ضروری (این مراحل باید در حساب Cloudflare انجام شوند):
1) در Workers & Pages، پروژه را از مخزن GitHub خود بسازید/وصل کنید؛ Root directory را پوشهٔ fastberry_site تنظیم کنید اگر مخزن ریشهٔ آن را دارد.
2) ایجاد D1 database با نام fastberry-db و اجرای schema.sql از بخش D1 Console.
3) ایجاد R2 bucket با نام fastberry-receipts.
4) از D1 دیتابیس، شناسهٔ database_id را بردارید و در wrangler.toml به جای REPLACE_WITH_D1_DATABASE_ID قرار دهید.
5) در Worker Settings > Variables and Secrets یک Secret با نام ADMIN_TOKEN و مقدار تصادفی قوی بسازید. هرگز این توکن را در GitHub یا فایل‌های عمومی قرار ندهید.
6) مطمئن شوید Build command خالی باشد و Deploy command برابر `npx wrangler deploy` باشد. اگر Cloudflare ساخت Git را در ریشهٔ مخزن اجرا می‌کند، فایل‌های همین پوشه باید در root پروژه قرار بگیرند.
7) پس از Deploy، صفحهٔ مدیریت از لینک «مدیریت» در پایین سایت در دسترس است؛ توکن ADMIN_TOKEN را در فرم مدیریت وارد کنید.

نکتهٔ امنیتی:
- این نسخه ورود/ثبت‌نام کاربران را عمداً جعلی جلوه نمی‌دهد؛ احراز هویت همکاران هنوز پیاده‌سازی نشده است.
- فعلاً کد پیگیری به تنهایی اطلاعات خلاصهٔ سفارش را نشان می‌دهد؛ برای داده‌های حساس بیشتر، باید مالکیت سفارش با حساب کاربری تأییدشده بررسی شود.
- مقدار توکن مدیر را فقط در Cloudflare Secret نگه دارید.
- اطلاعات بانکی را پس از ورود به پنل مدیریت ذخیره کنید؛ تا آن زمان صفحه می‌گوید اطلاعات پرداخت تنظیم نشده است.
